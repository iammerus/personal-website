## Why this matters

The redesign was built alongside the previous site instead of replacing it. The
old components, layouts, Vue composables, orphaned content, and images all still
ship. `astro-compress` throws `Sharp: Input file contains unsupported image
format` on the leftover images every build, and dead files make every other
plan noisier to read and riskier to change. Removing them makes the build clean
and the branch honest about what it actually is.

- Remove the imports for `astro-compress` and `astro-icon`.
- Remove the aliases `@post-images`, `@project-images`, `@composables`, `@utils`.
- Leave the `gsap` `ssr.noExternal` / `optimizeDeps` config untouched.
- Remove the `scss` `preprocessorOptions` block (no SCSS remains).

**Verify**: `pnpm build` → exit 0, "9 page(s) built".

### Step 4: Remove now-unused dependencies

For each of `astro-icon`, `astro-compress`, `@astrojs/partytown`, `sass`,
`sanitize-html`, `svgo`, confirm it is unreferenced in `src/` and `astro.config.mjs`:
```bash
grep -rn "astro-icon\|astro-compress\|partytown\|sanitize-html\|from 'sass'\|svgo" src astro.config.mjs
```
Remove from `package.json` only the ones with **no** matches. Then `pnpm install`.

**Verify**: `pnpm install` → exit 0; `pnpm build` → exit 0, "9 page(s) built", no Sharp error.

## Maintenance notes

- Removing `astro-compress` means HTML/CSS/JS are no longer minified at build.
  Cloudflare Pages applies gzip/brotli at the edge, so payload over the wire is
  largely unaffected; if bundle size later matters, re-add a compressor that
  skips images, or minify via Vite config rather than the leftover images route.
- A reviewer should confirm the diff is deletion-only outside `astro.config.mjs`
  and `package.json`, and that `pnpm-lock.yaml` changes are limited to removed deps.
